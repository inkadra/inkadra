# Inkadra 0.10.0

Inkadra 0.10 brings the Production board, a new set plan, a shooting schedule shaped like a calendar and videos in several resolutions. It is also the first release that native apps can safely write boards to: the board document moves from version 22 to 27, and the server tells apps which versions may write it.

## Highlights

- **Production board:** each project gets one board for its shooting days and its Troupe (the crew roster). The days of every board move there when the server starts (see "Read before upgrading").
- **Shooting schedule as a calendar** that saves itself: draw blocks on empty time, move whole days, scene blocks, day calls and block notes, conflicts, a phone list.
- **Set plan, new:** walls and openings, a library of 163 icons, snapping, power and grip, links to characters, frames, scenes and locations, the sun, locked items, and a PDF sheet for the shooting day.
- **Board types and modules:** several storyboards in a project, board cards that preview their board, a shorter toolbar, and Storyboard, Production, Moodboard, Client review and Set plan that each person can switch off in Settings → Modules.
- **Call sheets reworked:** key times, locations, inline pictures, the crew and the set plan's power.
- **Videos in several resolutions** with a Quality menu, streamed over HLS, also to guests of share links. Copies at a constant quality, HDR and 10-bit sources, and a Settings → Video page with presets.
- **Redesigned** Home, Inbox, Projects, the settings, the share dialog and the board versions timeline.
- **Media tools in the standard image:** video posters, playable copies, waveforms, RAW and PDF thumbnails no longer need a `-media` image.
- For administrators: an activity log (with CSV export), verified backups that can include files and go to their own S3 bucket, a database backup before every upgrade that migrates, and a load test in Settings → Server.

## Read before upgrading

- **Back up first.** The first start of 0.10 on a 0.9 database writes a backup of the database before migrating, and stops without migrating if it can't (check the free space in `/data/backups`).
- **Shooting days move to the Production board** of their project when the server starts. To hold the move back, set `PRODUCTION_BOARD_MOVE=false` in `.env` before upgrading. Details and the way back in `docs/self-hosting/upgrades.md`.
- **Board documents move from version 22 to 27.** Browser tabs and installed apps from 0.9 stay read-only on boards until they reload. Going back to 0.9 means restoring the backup taken before the upgrade, with 0.9.
- **`.env` reaches the container whole:** the new `compose.yaml` reads it with `env_file`, so every documented setting works from `.env` alone, and an empty line such as `OIDC_SCOPES=` means the default. Take it with 0.10, not with 0.9 (an empty line can stop 0.9 at start). If you start Compose with `--env-file <file>`, also set `INKADRA_ENV_FILE` to that file; a stack manager without a `.env` next to `compose.yaml` needs one, or `INKADRA_ENV_FILE`; variables set only in the shell no longer reach the container. A hand-edited copy of the old `compose.yaml` keeps working.
- **Remove `-media` from `INKADRA_TAG`:** the standard image now has the media tools, and `-media` images are no longer published. `-office` stays.
- **Safer defaults in the deployment files:** the Content-Security-Policy is enforced, HSTS is on with an https `PUBLIC_URL`, Postgres and Valkey sit on their own network, and the bundled proxies are the only trusted peer. Take the new `compose.yaml` and `deploy/` files; what to check is in `docs/self-hosting/upgrades.md`.
- **Board size limits:** a board takes at most 64 MiB and 20,000 cards (`BOARD_MAX_STATE_BYTES`, `BOARD_MAX_ELEMENTS`). Larger boards stay readable and accept deletions.

## More

- The Troupe, a private crew roster per project, linked to characters and accounts, with duplicate rows merged.
- The project's time zone, and sun times on the project clock.
- Settings search finds every setting and its data, and opens the row.
- Storage shows each project in its colour and each person with their avatar; a redesigned Largest files dialog.
- Inkadra's own calendar in every date field.
- One menu style, one focus ring, larger touch targets on phones.
- The export dialog lost its presets and the kickoff summary; the heading style moved into it.
- Notes and to-do lists stay around their text when resized.
- A scene's To bring appears in the Storyboard view; with Production off it can be read and ticked, not changed.

## For administrators

- The upgrade applies database migrations at startup, as usual, right after the automatic backup.
- `GET /livez`, `GET /readyz` and a `/metrics` endpoint; container health checks use `/livez`.
- Default resource limits on the containers (`INKADRA_MEM_LIMIT` and the others, overridable in `.env`) and rotated logs. Client IPs leave request logs unless `LOG_CLIENT_IP=true`.
- One process per role: `web` and `collab` each run once (a lease in Valkey); `worker` still scales.
- With `S3_PUBLIC_REDIRECT=true`, browsers fetch media straight from the bucket through signed links (off by default).
- Backups: `BACKUP_DIR`, optional files in the archive, `BACKUP_S3_*` for an off-host copy, and `backup restore-files`.
- A server refuses to start on a database a newer version migrated.
- Office previews as a one-command compose overlay (`deploy/compose.office.yaml`).
- A new image channel, `next` (and `next-office`): the latest release, stable or release candidate. `latest` stays stable releases only, `edge` follows `main`.
- A release is published only once its images are built, scanned and tagged.
- For native apps, `GET /api/v1/instance/version` lists the board document version (`docSchemaVersion`), the oldest version allowed to write it (`minWriterSchema`) and capabilities such as `min-writer-schema` and `board-restore-marker`.

## Known limits

- The four languages added in 0.9 are still not reviewed by native speakers.
- Native apps are not published yet.

## Fixes

- Offline edits, schedule drafts and expired sessions are no longer lost; set-aside edits can be restored into the board.
- Failed board stores are retried, writes are atomic, and the server survives a queue outage.
- Database errors answer 409 or 503 instead of a server error.
- Deleting a project while one of its boards is being saved no longer deadlocks.
- The prompt to update the installed web app no longer gets stuck when two updates arrive close together.
- Faster first load of the web app, search and the server's database queries.
- Fixes from testing 0.9 across the board, the schedule, videos, settings and translations.
