# 0.4.2 upgrade notes

## HTTPS authentication cookies

HTTPS installations now use `__Host-inkadra.*` cookies. **Everyone must sign in once
again after upgrading.** Pending invitations must be claimed again by opening their
original invitation links. HTTP development cookie names and existing app/clipper bearer
tokens are unchanged.

Better Auth supports a single session-cookie name, not legacy aliases. Keeping legacy
cookies would require a custom migration bridge shared by authentication, REST and
collaboration; 0.4.2 deliberately does not retain that fallback. Existing server sessions
still expire or can be revoked normally. See [the security decision](../decisions/0031-host-cookies-and-admin-enrollment.md).

## Administrator two-step verification

The administrator enrollment policy defaults off. Before enabling it, administrators
should enroll in two-step verification and save their recovery codes. OAuth-only accounts
can enroll using their authenticated provider session; password accounts confirm their password.
Administrators without enrollment are restricted to setup when the policy is on.
The instance setting itself is part of the same release (#234).

## Mobile sign-in

Custom redirect schemes can be intercepted by another app. PKCE protects code redemption
but does not verify ownership of the redirect handler. Verified Android App Links and iOS
Universal Links are planned; see [self-hosting sign-in](../self-hosting/sign-in.md).

The two-factor trust-device cookie also changes name. Devices previously marked as trusted
will be asked for a two-factor code once more. Legacy sessions are not deleted by this
upgrade: their entries may remain in **Sessions** until their normal expiry (up to 30 days),
or can be revoked there. In split deployments, update **web, collab and worker together**;
do not mix cookie names across roles during a rolling upgrade.

## Emergency administrator recovery

The policy can only be enabled by an administrator who already has verified two-step
verification. If all administrators nevertheless become blocked, an operator with host /
container access can disable only this instance policy without changing accounts or 2FA:

```sh
docker compose exec inkadra node /app/dist/main.js admin-2fa off
```

The service is called `inkadra` in both all-in-one and split mode (or run
`inkadra admin-2fa off` with the configured database on the host). Reload the browser after
running it. Other instance settings are preserved; no server restart is required. This
command does not remove anyone's TOTP secret or recovery codes. `unlock-auth` only clears
rate-limit budgets and does not disable the administrator policy.

For accounts without a credential password, managing TOTP secrets or backup codes requires
a sign-in less than 15 minutes old, including after the initial enrollment. Sign in again
through the provider when that window expires. Password accounts still confirm their password.

## Public API version metadata

`GET /api/v1/health` and `GET /api/v1/instance` no longer include `version`. This is an
intentional security change to the v1 response contract in 0.4.2; integrations must tolerate
the missing field. Signed-in clients can use `GET /api/v1/instance/version`, and administrator
diagnostics retain their version field. The settings footer uses the authenticated source;
the public sign-in page does not display a release. Older cached web clients may temporarily
show an empty version until refreshed. Update integrations and regenerate clients from the
new OpenAPI document when upgrading.

The contract exception above was **approved by the maintainer on 2026-10-29**, explicitly
without a deprecation period. **Before upgrading, update monitors and dashboards that read
`version` from `/api/v1/health` (or `/api/v1/instance`).** That field will be absent: use health
status/checks for liveness and dependency monitoring, and an authenticated version source
when the release identifier itself is needed. No public replacement version field is added.
