# 0.4.2 upgrade notes

## HTTPS authentication cookies

HTTPS installations now use `__Host-inkadra.*` cookies. **Everyone must sign in once
again after upgrading.** Pending invitations must be claimed again by opening their
original invitation links. HTTP development cookie names and existing app/clipper bearer
tokens are unchanged.

Better Auth supports a single session-cookie name, not legacy aliases. Keeping legacy
cookies would require a custom migration bridge shared by authentication, REST and
collaboration; 0.4.2 deliberately does not retain that fallback. Existing server sessions
still expire or can be revoked normally. See [the security decision](../decisions/0031-host-cookies-and-admin-enrollment.md).

## Administrator two-step verification

The administrator enrollment policy defaults off. Before enabling it, administrators
should enroll in two-step verification and save their recovery codes. OAuth-only accounts
can enroll using their authenticated provider session; password accounts confirm their password.
Administrators without enrollment are restricted to setup when the policy is on.
The instance setting contract is delivered in the separate contract follow-up to #225.

## Mobile sign-in

Custom redirect schemes can be intercepted by another app. PKCE protects code redemption
but does not verify ownership of the redirect handler. Verified Android App Links and iOS
Universal Links are planned; see [self-hosting sign-in](../self-hosting/sign-in.md).
