# Inkadra 0.10.1

Inkadra 0.10.1 fixes how the server stops in Docker: a stop or an update now saves the open boards and hands over to the new container at once. It also emails administrators about new releases and lets them invite someone with a link.

## Highlights

- **A stop reaches the server again:** a stop, an upgrade or a change to `.env` ended the server without its shutdown, so open boards were not saved on the way out and the new container waited up to 30 seconds before serving. Now it shuts down properly and its successor serves at once.
- **Release emails:** administrators get an email when a new Inkadra version is out, with its highlights and a button to Settings → Updates, following their notification email setting.
- **Invite links:** Settings → Members can create a one-use invitation link, valid for 1, 2 or 7 days, for someone whose email you don't know.

## Read before upgrading

- Nothing to do with the `compose.yaml` of the release, or with your own copy of an earlier one.
- **An entrypoint of your own:** if your compose file or `docker run` sets the entrypoint to `/usr/bin/tini -- /app/docker-entrypoint.sh`, set it to `/app/docker-entrypoint.sh` alone, which now starts `tini` itself. Otherwise a stop still skips the shutdown. `command:` needs nothing.

## More

- Pending invitations show invitation links too, with Copy link and Revoke; a used link drops out of the list.
- The release email reads the release notes in the administrator's language, or in English.

## For administrators

- The image's `ENTRYPOINT` is now `/app/docker-entrypoint.sh`, which drops to the `node` user and then runs `tini` and the server. `tini` stays PID 1 and keeps reaping the worker's child processes.
- A lease that fails to be released at shutdown is now logged as a warning; it still never stops the shutdown.
- No database migration and no change to the board document: the upgrade from 0.10.0 writes no backup before starting, and going back to 0.10.0 is a matter of setting `INKADRA_TAG=0.10.0` again.

## Fixes

- Boards open at the moment of a stop or an update are saved before the server exits (#926).
- A recreated container no longer waits for the lease of the one it replaces.
